# 分析层优化与验证记录

本轮按收益实施了正确性修复、语义补全、大结果存储与性能优化。真实 trace 按用户要求跳过；本报告的规模结果仅代表合成测试负载。

## 已完成

1. **正确性**：过滤范围与缓存隔离、零基半开区间、线程寄存器 producer 隔离、唯一证据关联及去重、访存类型比较、Capstone 比较别名读写修正、v5 索引首条 delta 与迭代器重复解引用修正。
2. **语义覆盖**：显式 NZCV、整向量 SIMD、GPR/向量/内存传播、多线程共享内存与独立寄存器状态；可选动态控制依赖、后支配汇合点、调用深度作用域及控制来源输出。
3. **熵分析**：完整区域直方图取代页面熵平均；历史快照按查询时间重建；时间线增量更新，处理全区域、首读、old_value 与半开指令边界。
4. **反向访问**：有界窗口顺序读取、倒序消费；复制记录以摆脱压缩缓存块指针生命周期；密集写依赖降低随机索引查询频率。
5. **大结果**：固定分块与匿名临时文件映射，避免连续 vector 翻倍峰值；POSIX 每个容器共享一个临时文件，顺序再读时重映射前一块以释放驻留页。大 DFG 使用 CSR，污点导航在大结果上使用二分搜索。
6. **xref**：压缩位图实际工作集检查，超过预算才切换有界外部排序；最多 32 路归并，逐 PC 写位图、按需读结果。重复 PC 小工作集可直接聚合。
7. **资源与失败处理**：工作预算、可选 RSS 停止阈值、取消检查、collector abort、异常转 Failed；失败扫描不作为完整结果落缓存。结果质量字段与 CLI/MCP 配置和输出同步。

缓存目录为 `pass_cache/v3`。旧版本分析结果不自动复用，trace 索引无需因此重建。DFG 自身的语义序列化版本也已更新。

## 复杂度与取舍

| 路径 | 时间 | 额外存储及取舍 |
|---|---|---|
| xref 位图聚合 | O(N)，输出另需 O(U log U) 排序 PC | O(U + 压缩位图)，实际超预算后切换 |
| xref 外部排序 | O(N log N)，归并受 run 数影响 | 固定 run 缓冲与临时磁盘；一个 PC 的输出位图及元数据另占空间 |
| 密集反向污点 | 约 O(N + E) | 每窗口一次索引定位；事件/边可落盘；活跃污点、嵌套对象另占堆 |
| DFG 邻接 | O(V + E) 构造 | 分块节点/边及映射 CSR；查询与节点度数相关 |
| 熵时间线 | O(K + R + 256T) | K 为重建快照成本，R 为覆盖字节更新量，T 为采样数；避免每次采样重新回放 |
| 动态控制依赖 | 两次 O(N) 回放及后支配迭代 | O(U + CFG 边数) 图，O(N) 控制父节点可落盘；后支配迭代不保证线性最坏界 |

N 为指令数，U 为唯一 PC 数，V/E 为依赖图节点/边。外部排序是内存与时间的取舍，不承诺快于无限制内存版本。启用扫描资源限制时，collector 融合采用顺序扫描，避免并行克隆突破预算；独立 pass 仍可并行。

`--analysis-memory-mb` 约束分析工作集策略，不是进程硬 RSS 上限。trace 映射、RocksDB、解码缓存、唯一 PC 元数据、活跃污点及嵌套 vector/string 分配仍占内存。`--rss-limit-mb` 通过周期检查停止，存在检查间隔内的超额。临时文件空间与最终结果规模相关，磁盘不足作为分析失败返回。

## 精度边界

- SIMD 为整寄存器保守依赖，未实现 lane/bit 精确追踪。
- 控制依赖是动态模型。未观测路径、间接跳转及缺失汇合点通过 `unresolved_control_joins` 报告；不能据此声称完整静态控制流或位级证明。
- `quality.has_gaps=false` 仅描述访问到的指令及当前支持模型。索引跳过的指令不算已验证。
- 当前验证平台为 macOS Apple Silicon，构建关闭 Triton。新配置在不适用 Triton 时明确使用解码操作数引擎；Windows/Linux 与 Triton 构建未在本机运行验证。

## 复现

```sh
cmake --build slowmo/build-no-triton -j 4
ctest --test-dir slowmo/build-no-triton --output-on-failure -j 4
python3 slowmo/bench/run_analysis_scale.py \
  --scales 1000000,10000000 --formats v4,v5,block --threads 1,4 \
  --repeats 3 --reference \
  --output slowmo/bench/results/analysis_scale_verified.json
```

规模脚本在私有临时目录生成 trace，结束后删除；未来传入 `--trace /absolute/path/file.trace` 时只操作私有硬链接/副本，不删除原索引。cold 表示清理 persisted pass 结果，首个查询还构建私有索引；操作系统页缓存未控制，内存页历史索引仍可跨查询复用。因此数据中的 pass 时间、索引构建时间与 wall 时间应分别阅读。`--reference` 是当前代码的无限制内存 xref 路径，不是整个项目优化前的性能基线。RSS 为分析阶段每 2 ms 采样的进程驻留量，包含基础设施，可能漏掉更短峰值，不包含采样开始前的索引构建峰值。

## 最终验证结果

完整构建成功；CTest **783/783** 通过（320.85 s）。新增回归覆盖 v5 PC oracle、重复解引用、跨压缩块缓存淘汰、线程共享内存/独立寄存器、SIMD 标量往返、控制依赖汇合、历史/跨页熵、外部归并、预算失败、CSR 查询，以及数千分块共享临时文件描述符。
