交互浏览回答的问题不同于批处理分析：不仅是“检测到了什么”，更是“这个精确时刻的状态是什么”。Desktop 与 TUI 共享同一时间轴、状态模型、Pass 结果、书签和导航语义。

## 从时间轴开始

通过 `inst_id` 选择一次具体执行。主指令行组合运行时 PC、反汇编和内存访问；寄存器与内存面板跟随光标，展示该次执行的真实状态，而不是静态近似。

## 按证据移动

| 目标 | 导航动作 |
|---|---|
| 重访位置 | Goto PC 或指令 ID |
| 在同一 PC 的多次执行间移动 | 上一个/下一个 XRef |
| 跟踪动态调用 | 调用栈、Follow Call、Follow Return |
| 定位值变化 | Register Timeline 或内存写历史 |
| 在事件处停下 | PC 断点、写观察点、条件断点 |
| 回顾调查过程 | 前进/后退历史与书签 |
| 遍历污点证据 | 上一条/下一条污点指令 |

## 检查状态

- **Registers：** 选中指令执行前/后的完整 GPR，并高亮读写寄存器。
- **Memory：** 已记录访问、时间感知区域读取、最后写入者与写历史。
- **Hex Dump：** 选定地址和时刻的已知/未知字节。
- **Call Stack：** 动态重建的栈帧，包括已观察到的尾调用上下文。
- **Functions 与 CFG：** 从真实执行控制流恢复的结构。

## 在上下文中触发分析

使用指令右键菜单或 Analysis 控制台，从当前位置启动前向/反向污点、XRef、CFG、内存快照等 Pass。结果会被缓存，可以直接重访而无需重复扫描。

视觉多面板工作请看 [Desktop GUI](./desktop/)，终端环境请看 [TUI](./tui/)，精确移动方式见[导航与断点](./navigation/)。
